## Этап 8 — анти-чит, производительность, автотесты

Всё запускается одной командой. Сводка PASS/FAIL, код выхода 0 = всё прошло:

```powershell
powershell -ExecutionPolicy Bypass -File Scripts\run_tests.ps1                    # сборка редактора
powershell -ExecutionPolicy Bypass -File Scripts\run_tests.ps1 -Packaged -Network # упакованная Development + 2 клиента
powershell -ExecutionPolicy Bypass -File Scripts\run_tests.ps1 -Only unit,cheat   # выборочно
```

| Набор | Флаги | Что проверяет |
|---|---|---|
| `unit` | UE Automation `CSFusion.Unit.*` без графики | урон и падение урона с дистанцией, зоны попадания, порядок сложности ботов, ограничения настроек, все сценарии `FCSCheatGuard` (бег, speed hack, телепорт, респаун, лаг, флуд, законная автоматическая стрельба) |
| `input` | `-cstestinput` | движение, поворот мыши, выстрел |
| `loot` | `-cstestloot` | подбор, экипировка, стрельба из инвентаря, выброс |
| `doubledrop` | `-cstestdoubledrop` | лут не выпадает дважды |
| `ui` | `-cstestui` | экран инвентаря, ESC-меню, применение настроек |
| `bots` | `-bots=4 -cstestbots` | боты ходят, стреляют, убивают, подбирают лут |
| `cheat` | `-cstestcheat` | клиент ведёт себя как взломанный, авторитет всё отклоняет (см. ниже) |
| `perf` | `-bots=8 -cstestperf` | 20 с замера времени кадра после прогрева; бюджет p95 ≤ 33.3 мс |
| `netcheat` | `-Network` | то же, что `cheat`, но B — обычный клиент в комнате Photon, а A — мастер; в логе A должно быть `SUSPENDED` |

Что делает `-cstestcheat`:
- 10 выстрелов за один кадр — засчитан один;
- выстрел из точки в 20 м от пешки — отклонён;
- подбор предмета в 15+ м — отклонён;
- 60 переключений слота за кадр — флуд, страйк;
- телепорт на 15 м — игрок заблокирован, обычный выстрел отклонён;
- через 10 с блок снят, выстрел проходит.

Найдено и исправлено на этом этапе:
- `FCSCheatGuard` признаком «ведро ещё не начато» считал нулевое время,
  поэтому при запросах ровно в момент 0 bucket наполнялся заново при каждом
  вызове. На сетевых часах такое почти не случается, но ошибку поймал
  модульный тест, и теперь для этого есть отдельный флаг;
- в первой версии `run_tests.ps1` для упакованной сборки закрывался только
  лаунчер `CSFusion.exe`, а сама игра (`Binaries\Win64\CSFusion.exe`)
  оставалась запущенной. Копии копились, и замер показал 39 FPS вместо 332.
  Теперь скрипт запускает игру напрямую;
- при входе в комнату по сети срабатывал `ensure(IsValid(MappingContext))`
  в Enhanced Input, и появлялось окно отчёта об ошибке. Причина: runtime
  mapping context принадлежит пешке, и когда Fusion перезагружал карту,
  пешка уничтожалась, а контекст оставался зарегистрированным. Теперь
  пешка снимает его в `EndPlay`. **Ошибка была и в прошлых версиях**
  (с v0.5.0). `run_tests.ps1` теперь считает провалом любой
  ensure, assert или падение в логе.

- **Смена хоста замораживала ботов.** Новый мастер принимал счётчики
  респаунов ботов за свежий респаун и переносил всех ботов на одну точку.
  Там они застревали друг в друге, переставали видеть и двигаться. Теперь
  копия, которой управляет другой пир, отслеживает счётчик. Бот-тест теперь
  проверяет и застревание: живой бот, стоящий на месте больше 30 секунд,
  даёт `BOTS BROKEN`.
- **Офлайн-тренировка без раундов:** матч стоял в WAITING FOR PLAYERS.
- **Первое объявление фазы терялось** (`Missing Function Descriptor`),
  а объявления вообще не показывались. Теперь это баннеры из фазы в HUD.
- **Игрок над лутом мешал его подобрать:** проверка видимости учитывала
  чужие капсулы. Теперь учитываются только стены.
- **Взгляд после респауна мог смотреть в небо:** у точек спавна 4–7 был
  крен 180°. Теперь используется только yaw точки.
- **F1 в Development-сборках включала каркасный режим отображения.** Таблица
  переехала на `Q`.
- Тесты стали честнее: подход к предметам без телепортов (анти-чит
  справедливо наказывал), ожидание соперника, прицеливание при контрольном
  выстреле (одиночный выстрел от бедра на 6 м иногда уходил мимо капсулы),
  поиск строк с учётом регистра.

## v2.0, фаза 1: безопасность бэкенда и вход

Смена ника игроком в v2.0 убрана. Проверка `rename:` выше относится к v1.2.

### База: `Backend/supabase/tests/security_tests.sql`

Запускается в SQL Editor после миграций. Всё выполняется внутри одного блока,
который в конце всегда бросает исключение: тестовые данные откатываются, а
результат виден в тексте ошибки (`CS-FUSION SECURITY TESTS: N passed, 0 failed.`).

Роли имитируются так же, как это делает PostgREST: `SET ROLE anon` или
`authenticated` плюс `request.jwt.claims`. Что проверяется:

- **Анонимный клиент и игрок:**
  - не видят Epic ID, роли и баны;
  - видят `id`, ник и таблицу лидеров;
  - не видят журнал, билеты и строки матчей.
- **Игрок ничего не пишет:**
  - не меняет ник;
  - не меняет свою роль и бан;
  - не пишет статистику и профили.
- **Игрок и даже токен админа не вызывают функции напрямую:** `admin_*`,
  `match_*`, `cs_*` через REST недоступны, старой `apply_match_result` больше нет.
- **Роли:**
  - игрок не проходит AdminService;
  - модератор: бан до 7 дней — да; навсегда, роли, задать ник, сброс
    статистики, аннулирование матча — нет; сброс ника — да;
  - админ: делает модератора — да, делает админа — нет;
  - superadmin: делает админа — да, `superadmin` через API не выдаётся;
  - никто не действует над собой и над равным или старшим;
  - бан без причины отклоняется;
  - занятый или зарезервированный ник отклоняется;
  - забаненный админ бессилен.
- **Журнал:**
  - бан и смена роли записаны с причиной, старым и новым значением;
  - модератор не видит чужие действия.
- **Матчи:**
  - честный отчёт засчитан ровно один раз и повторно не принимается;
  - не участник отчитаться не может;
  - 16 копий одного игрока, 300 убийств за 5 минут и чужой билет дают
    подозрительный матч без изменения статистики;
  - аннулирование вычитает матч обратно;
  - офлайн-матч идёт в статистику тренировок;
  - билет на чужой офлайн-матч и забаненному не выдаётся;
  - 31-й старт матча за час отклоняется.

### Живой бэкенд глазами изменённого клиента: `-cstestmenu=backendprobe`

```
UnrealEditor.exe CSFusion.uproject -game -cstestmenu=backendprobe
```

Нужен вход в Epic. Игра обращается к функциям `admin` и `match` в обход
собственных проверок, как это сделал бы изменённый клиент. Сервер должен
отказать:

- у игрока — любое админ-действие (403);
- у любого — бан себя, выдача себе `superadmin`, смена своего ника;
- отчёт и билет для несуществующего матча (404);
- матч с выдуманным режимом (400).

Итог — строка `BACKEND PROBE RESULT: ... -> BACKEND PROBE OK`. В Shipping
этого кода нет.

### Вход без окна: `-cstestlogin`

При втором и следующих запусках в логе должно быть
`Accounts: Epic sign-in OK (saved session, no window)`. Токены в лог не
пишутся.
